# 《越南语趣味大剧场》｜每集视频强制质量验收清单 v1.0

> **适用范围：今后每一次渲染、重渲染和发布前。** 视频能播放、ffprobe成功、文件上传成功，**都不能直接等于“合格成片”**。请先读 [当前任务首页](./CURRENT_STATUS.md)。

## A. 渲染前检查（防错版、缺素材）

- [ ] **唯一身份**：展示排序号、剧集编号（如 EP05/Z003）和版本号 v01/v02 分别写清。旧版已在发布的不修改。
- [ ] **输入一致**：原 MP3、JSON、剧情说明来自**同一集号和版本**；若有重复文件，核真实文件ID、版本、音频内容，不能只按上传时间或标题匹配。
- [ ] **源音频解码**：检查可播放性、采样率、有效非静音时长、起止截断、明显爆音、突然静音、卡壳/机械重复、读错人物/越南语。试听开头、中段、末段以及问题时间点。
- [ ] **时间轴**：JSON时间轴最后 end_ms 与MP3实际长度对比，检查首句/末句、重叠抢话、异常空白、明显不合逻辑时长。
- [ ] **角色**：15人编号-姓名-声线-表情编号一一对应；姓名/角色穿帮不得强制映射；旧12人单独兼容。
- [ ] **词语**：越南语词义核对，谐音仅用已审 JSON 中明确存在的字段，不擅自编写。虚构剧情按剧本演绎，不额外当新闻核查。

## B. 渲染后机检（必须留实际数值/证据）

- [ ] **媒体完整**：MP4 能从0秒读到最后一帧，解码无故障；ffprobe视频编码H.264、像素1080×1920、帧率目标30fps、音频AAC，文件内有真实画面与声音。
- [ ] **长度一致**：记录MP3实际时长、JSON末轴、MP4视频时长、MP4音频时长；差异写毫秒数并解释。**不能仅因为三者接近就认定故事完整**。
- [ ] **音源一致**：从MP4解码出音轨和原 MP3 对比（允许BGM/SFX干扰，采用分段试听、波形/相关性辅证），防止06式旧音轨错配。
- [ ] **静帧/黑屏/卡顿**：检查黑帧、冻结、时间戳不连续、重复帧、掉帧、画面加载停滞；可用 ffmpeg `blackdetect`、`freezedetect`、帧PTS分析作为辅助证据。**大量静止画面不一定代表技术故障，但在群聊连续滚动片里必须解释是否符合设计**。
- [ ] **声音异常**：检查不合理的长静音、爆音、音量骤变、破音、口吃重复、BGM盖住人声、音效不适当；可用 `silencedetect` 作为候选问题定位，必须实际试听确认，不因自然停顿机械判错。
- [ ] **流畅度**：实际抽取连续帧看运动，不只看“30fps”元数据；采样关键帧复制编码的方案需显式标记“非原生30fps逐帧动画”，不能冒充原生流畅渲染。

## C. 逐句/逐屏人工审片（不能仅靠技术指标取代）

- [ ] **完整从头看到尾，带声音**：实际看完本集，不只抽开头/中间/结束帧；不具备播放/听全片条件时在报告中明确“仅抽检，待终验”，不得标可发布。
- [ ] **字幕逐句核对**：逐条检查台词是否和声音一致，越语拼写/声调与中文词义、错别字、漏字、重字、串句、中文断行、换行溢出、字卡覆盖、过早/过晚消失。
- [ ] **头像/气泡/动态**：每句话说话人头像与角色名是否正确，9宫格表情是否贴合，群主左右位置/气泡方向正确，滚动是否自然、是否无故停顿/飞快跳帧/穿屏。
- [ ] **重点时间窗**：0～3秒开头钩子；每条台词开始与结束各前后约0.5秒；每次抢话重叠、音效点、词卡出现点；全片中段；**最后5秒及最后一句完整收尾**，不能出现“讲到一半突然结束”。
- [ ] **用户实际手机观看**：竖屏预览尺寸适合iPhone，标题、越语卡在安全区内可读，不能被UI或大弹窗遮住内容；封面独立3:4，真实角色一致。
- [ ] **剧情不是只有时长**：不能凭“源音轨刚好结束”就认定故事讲完。若故事明显只有半截，应标“源内容不足/待补剧本与配音”，不得用重复视频、拉长静帧或虚构时长糊弄。

## D. 验收结论、归档及复检门槛

- **结论只能三选一：**
  - **通过 / 可发布**：关键项全部通过、可访问的正式成片和文字/音画验收证据齐备；不代表已在社媒发布。
  - **未通过 / 待返工**：发现截断、错音轨、字幕错、明显卡顿、头像错误、词卡遮挡、剧情不完整等关键问题；记时间码与修法，**禁止称成品**。
  - **未验证 / 待终验**：不能播放听完整视频、只做抽检、素材缺失或权限阻塞等；不能冒充通过。
- **修复**：保留原 v01 与所有源文件；新增 v02（或下一版本）；修复后**全片重新按A～D复测**，不是“修了局部就完成”。
- **归档**：在每集文件夹的“06_发布文案＋首条评论＋交付记录”加入验收结果、版本、QA证据；未通过片在名称/记录中明确“待修/不可发布”，不要覆盖已通过的旧片。
- **接力**：在 [CURRENT_STATUS.md](./CURRENT_STATUS.md) 修改最新结论和责任任务，给出 MP4/MP3/JSON/封面/文案/报告的真实Drive链接；[AI_HANDOFF.md](./AI_HANDOFF.md) 追加执行日志并附GitHub commit、Action run、阻碍事项。
